# 当前 Sprint — 后端安全与基线

## Sprint 目标

在加入高级检索或工作流能力之前，将当前可运行的 Agent 原型转变为更安全、可测量的基线。

除非被明确要求，否则本 Sprint 不实现后续路线图阶段。

---

## 当前优先级

### P0 — 建立基线

- 记录当前 Agent 执行流程；
- 记录当前检索流程；
- 保留现有 FTS 和向量检索行为；
- 识别有代表性的回归案例；
- 记录现有测试状态。

### P1 — Agent Tool 安全

- 将 Agent Tool 分类为 READ / WRITE / DESTRUCTIVE；
- 引入确定性的授权/策略校验；
- 防止已检索文档内容绕过 Tool 策略；
- 为破坏性操作准备明确的审批行为；
- 增加安全回归测试。

### P1 — 阻塞 I/O

审计异步 endpoint 中的以下操作：

- 同步 psycopg；
- 文件系统操作；
- PDF/DOCX 解析；
- 同步外部 HTTP 调用。

修正事件循环阻塞问题，但不要盲目把整个应用转换为异步。

### P1 — PostgreSQL 连接生命周期

以合适的连接池策略替换不受控制的按调用创建连接。

保留清晰的事务边界。

### P1 — PDF 资源安全

加入实用的资源限制：

- 页数；
- 提取文本大小；
- 解析超时或等价的受限执行方式；
- 明确的失败状态。

### P1 — 任务删除备份设计

移除“删除单个任务时生成全数据库 JSON 备份”的行为。

若需要审计或恢复能力，应采用范围受控的设计，例如审计记录或软删除。

---

## 必需测试

增加或加强以下测试：

- Tool 风险分类；
- 未授权 Tool 访问；
- 破坏性操作行为；
- 跨用户隔离；
- 在可行范围内测试数据库连接行为；
- 阻塞 I/O 重构回归；
- 上传/解析器资源限制。

---

## 本 Sprint 明确不在范围内的内容

除非单独提出请求，否则不要加入：

- 混合检索；
- 重排序器；
- Agentic Retrieval；
- LangGraph；
- MCP；
- 多 Agent；
- Redis；
- GraphRAG；
- AgentEval Studio。

本 Sprint 稳定后，检索评估是下一个主要阶段。

---

## Sprint 完成标准

满足以下条件时，本 Sprint 完成：

1. 当前基线已文档化；
2. Agent 修改操作具有明确、确定性的安全边界；
3. 破坏性操作不能仅因 LLM 发出请求就静默执行；
4. 主要异步 endpoint 不再直接在事件循环中执行昂贵的同步工作；
5. PostgreSQL 连接管理已受控；
6. PDF 解析具有资源限制；
7. 删除任务不再生成无范围限制的全数据库备份；
8. 相关测试通过；
9. 文档反映真实实现。

满足这些标准后，在开始“检索评估”前更新本文件。
